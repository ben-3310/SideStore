# Переносимые локальные зависимости

## Цель

Физически хранить локальные зависимости SideStore вне корня репозитория, не
меняя контракт путей для Xcode, SwiftPM, заголовков и build scripts:
`Dependencies/...` остаётся единственной точкой доступа.

## Контекст

`AltStore.xcodeproj` использует относительные пути `Dependencies/AltSign`,
`Dependencies/minimuxer` и `Dependencies/em_proxy`. В проекте уже существует
корневой символический link `Dependencies`, однако он содержит абсолютный
пользовательский путь. Такой link работает только на машине, где он создан.

## Выбранное решение

1. Заменить корневой link на относительный:
   `Dependencies -> ../SideStore_Dependencies`.
2. Добавить проверяемый bootstrap-скрипт, который не меняет файловую систему.
   Он завершает работу с понятной ошибкой, когда `Dependencies` отсутствует,
   не является символической ссылкой, ведёт не на каталог или указывает не на
   ожидаемый соседний каталог.
3. Добавить краткую документацию для разработчика: структура каталогов,
   безопасная одноразовая команда создания link и команда проверки.
4. Запускать проверку до локальных проверок/CI, которые используют Xcode.

## Границы

Не изменяются относительные пути в `.pbxproj`, исходный код, содержимое
`SideStore_Dependencies` и gitlink-подмодули внутри него. Скрипт не создаёт,
не удаляет и не заменяет `Dependencies`: создание или замена link остаётся
явным действием разработчика.

## Поток работы

После clone разработчик размещает `SideStore` и `SideStore_Dependencies` рядом.
Он создаёт относительный link в корне `SideStore`, затем запускает проверку.
Xcode по-прежнему открывает пути через `${PROJECT_DIR}/Dependencies` и не
получает сведений о физическом расположении зависимости.

## Ошибки

Проверка должна вернуть ненулевой код и вывести инструкцию исправления для
каждого случая: отсутствующий путь, обычная папка вместо link, несуществующая
цель и неканоническая цель. Она не пытается автоматически исправлять ни один
из случаев, чтобы не затереть пользовательские данные.

## Проверка

Сначала добавляются shell-тесты для успешной относительной ссылки и всех
ошибочных состояний. Каждый тест должен быть зафиксирован как RED до
реализации проверки. После реализации запускаются эти тесты, затем актуальная
проектная smoke/build-проверка, не изменяющая зависимости.
