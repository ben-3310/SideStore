# Локальный запуск SideStore на физическом iPhone — дизайн

## Цель

Добавить воспроизводимый локальный контур, который собирает Debug-версию
SideStore с подписью Xcode, запускает один детерминированный UI smoke-тест на
подключённом физическом iPhone 13 с iOS 27, устанавливает приложение и оставляет
его запущенным на телефоне. GitHub Actions и пользователи GitHub Runner в эту
задачу не входят.

## Подтверждённое исходное состояние

- Базовая версия проекта — `ben-3310/SideStore:develop` на коммите
  `3b7f4b4c5a3afb0a4f24d4b05f75e92b9bb09e39`.
- Используется Xcode 27.0 (`27A5194q`) из уже выбранного
  `/Applications/Xcode-beta.app`.
- Xcode видит ровно один проводной iPhone 13 с iOS 27.0 как допустимый
  destination; устройство paired, разблокирован Developer Mode.
- Для текущего пользователя доступны Apple Development identities и локальные
  provisioning profiles. Схема SideStore использует Automatic Signing.
- Debug bundle identifier имеет отдельный командный суффикс и не совпадает с
  Release bundle identifier. На телефоне сейчас нет SideStore с этим Debug
  bundle identifier, поэтому существующее пользовательское приложение и его
  контейнер не будут заменены.
- В исходной точке проходят 17 существующих Python-регрессионных тестов.

## Выбранный подход

Создать отдельный локальный инструмент `scripts/device/run_on_iphone.py`. Он не
будет переиспользовать simulator-only команды из `scripts/ci/workflow.py` и не
будет менять workflow-файлы. Инструмент выполнит один последовательный сценарий:

1. Получит список устройств через JSON-интерфейс `devicectl` во временный файл.
2. Выберет ровно один paired physical iPhone 13 с iOS 27 и включённым Developer
   Mode. При нуле или нескольких подходящих устройствах завершится до сборки.
3. Передаст Xcode точный идентификатор устройства только как аргумент процесса;
   идентификатор не будет печататься, сохраняться в логах проекта или попадать в
   Git.
4. Выполнит подписанный `xcodebuild build-for-testing` для Debug-конфигурации,
   схемы SideStore и точного physical-device destination в отдельном
   `build/device/DerivedData`.
5. Проверит подпись полученного `SideStore.app` через `codesign --verify`.
6. Выполнит только
   `UITests/UITestsLaunchTests/testLaunch` через
   `xcodebuild test-without-building` и сохранит результат в
   `build/device/SideStore-Device.xcresult`.
7. Проверит summary результата: один выполненный тест, ноль ошибок и ноль
   пропусков.
8. Установит собранный Debug app через `devicectl device install app`, затем
   запустит его в foreground через `devicectl device process launch
   --terminate-existing`.
9. Подтвердит, что процесс приложения остаётся живым после короткого окна
   стабильности. Временные JSON-файлы будут удалены даже при ошибке.

Все дочерние процессы запускаются списками аргументов без `shell=True`.
Вывод `xcodebuild` и `devicectl` проходит через redactor, который заменяет
выбранный CoreDevice identifier и совпадающие device-ID значения до записи в
терминал или файл. Чувствительные значения не включаются в сообщения об
ошибках.

## Подпись и provisioning

Первая попытка использует существующие локальные identities и profiles без
обновления Apple Developer state. Если Xcode сообщает только об отсутствующем
или устаревшем provisioning profile, допускается одна повторная попытка с
`-allowProvisioningUpdates`. Инструмент не использует
`-allowProvisioningDeviceRegistration`, не создаёт сертификаты и не изменяет
`Build.xcconfig`.

Если Xcode требует интерактивный вход в Apple Account, регистрацию устройства
или исправление entitlements, выполнение останавливается с очищенным сообщением
об ошибке. Такие изменения не маскируются ослаблением подписи: физическое
устройство должно получить нормально подписанную сборку.

## Безопасность устройства

- Устанавливается только Debug-приложение с отдельным bundle identifier.
- Существующие приложения, контейнеры, pairing-файлы и provisioning profiles не
  удаляются и не очищаются.
- Инструмент не изменяет Wi-Fi, Remote Pairing, DDI или системные настройки
  телефона.
- Телефон должен оставаться подключённым по USB, разблокированным и доступным
  Xcode на время сборки и теста.
- При неуспешной установке или тесте автоматическое удаление приложений не
  выполняется: состояние сохраняется для адресной диагностики.

## Границы проверки

Успешный launch smoke доказывает, что проект компилируется и подписывается для
arm64 device, устанавливается на iOS 27 и выходит в foreground без немедленного
краша. Он не доказывает работу Apple Account, VPN, Remote Pairing, фонового
обновления или установки стороннего IPA. Эти сценарии требуют отдельных
учётных данных, сетевого состояния и тестовых критериев и не входят в текущую
задачу.

## Автоматические тесты инструмента

Файл `scripts/device/test_run_on_iphone.py` на стандартном `unittest` проверит:

- выбор единственного подходящего iPhone без вывода идентификатора;
- отказ при нуле или нескольких подходящих устройствах;
- отказ для simulator, неподходящей версии iOS, выключенного Developer Mode или
  непарного устройства;
- построение Xcode-команд с exact-ID destination, Debug-конфигурацией и без
  отключения code signing;
- явное ограничение XCTest до одного launch-теста;
- проверку summary с `totalTestCount == 1`, `failedTests == 0` и
  `skippedTests == 0`;
- формирование install/launch-команд без shell и без идентификатора в
  пользовательском выводе;
- удаление временных файлов на успешном и ошибочном пути.

Тесты пишутся до реализации и должны сначала завершиться ожидаемым FAIL.

## Критерии готовности

1. Новые unit-тесты и все 17 существующих регрессионных тестов проходят.
2. `git diff --check` и целевой `actionlint` остаются зелёными; workflow-файлы не
   изменены.
3. Xcode успешно создаёт подписанный Debug `SideStore.app` для физического
   iPhone 13 с iOS 27.
4. XCTest result сообщает ровно один пройденный launch-тест без ошибок и
   пропусков.
5. Debug SideStore установлен и запущен в foreground на телефоне без
   немедленного краша.
6. В Git diff, логах и отчёте отсутствуют UDID, CoreDevice identifiers, данные
   Apple Account, сертификаты и provisioning UUID.
7. Публикация, если понадобится, выполняется только в `ben-3310/SideStore`;
   `SideStore/SideStore` не изменяется.
