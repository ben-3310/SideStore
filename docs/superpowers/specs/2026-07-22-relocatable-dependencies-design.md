# Переносимые локальные зависимости

## Цель

Физически хранить локальные зависимости SideStore вне корня репозитория, не
меняя контракт путей для Xcode, SwiftPM, заголовков и build scripts:
`Dependencies/...` остаётся единственной точкой доступа.

## Контекст

`AltStore.xcodeproj` использует относительные пути `Dependencies/AltSign`,
`Dependencies/minimuxer` и `Dependencies/em_proxy`. В проекте уже существует
корневой символический link `Dependencies`, однако он содержит абсолютный
пользовательский путь. Такой link работает только на машине, где он создан.

## Выбранное решение

1. Для локальной разработки использовать корневой link с относительной целью.
   Основной checkout может использовать рекомендуемый пример
   `Dependencies -> ../SideStore_Dependencies`; проверяемый код не привязан к
   этому буквальному пути и принимает любую относительную цель, которая
   разрешается в полноценный каталог зависимостей.
2. Добавить проверяемый bootstrap-скрипт, который не меняет файловую систему.
   Он принимает два эквивалентных состояния: существующий каталог
   `Dependencies` из рекурсивного Git checkout или существующую символическую
   ссылку на каталог. Он завершает работу с понятной ошибкой, когда путь
   отсутствует, является файлом либо ссылкой на несуществующую цель.
3. Добавить краткую документацию для разработчика: структура каталогов,
   безопасная одноразовая команда создания link и команда проверки.
4. Запускать проверку до локальных проверок/CI, которые используют Xcode.

## Границы

Не изменяются относительные пути в `.pbxproj`, исходный код, содержимое
`SideStore_Dependencies` и gitlink-подмодули внутри него. Скрипт не создаёт,
не удаляет и не заменяет `Dependencies`: создание или замена link остаётся
явным действием разработчика.

## Поток работы

После clone разработчик может разместить `SideStore` и
`SideStore_Dependencies` рядом, создать относительный link в корне `SideStore`
и запустить проверку. В чистом CI checkout Git создаёт обычный каталог
`Dependencies` и заполняет его зарегистрированными submodule; проверка
принимает это состояние. Xcode по-прежнему открывает пути через
`${PROJECT_DIR}/Dependencies` и не получает сведений о физическом расположении
локальной зависимости.

## Ошибки

Проверка должна вернуть ненулевой код и вывести инструкцию исправления для
каждого случая: отсутствующий путь, обычный файл вместо каталога или link и
несуществующая цель link. Абсолютная цель link отклоняется; относительная цель
проверяется после разрешения на наличие требуемых каталогов. Она не пытается
автоматически исправлять ни один из случаев, чтобы не затереть пользовательские
данные.

## Проверка

Сначала добавляются shell-тесты для успешной относительной ссылки, обычного
каталога из CI checkout и всех ошибочных состояний. Каждый тест должен быть
зафиксирован как RED до реализации проверки. После реализации запускаются эти
тесты, затем актуальная проектная smoke/build-проверка, не изменяющая
зависимости.
