# Дизайн: первая сборка ben4Store в TestFlight

## Цель

Собрать и передать в существующую внутреннюю группу TestFlight первую
обработанную iOS-сборку приложения `ben4Store` из текущего checkout.

## Границы

- Используется существующая запись App Store Connect `ben4Store` с bundle ID
  `com.SideStore.benStore.972MD5K36E`.
- Не создаётся новая запись приложения и не выполняется отправка на App Review.
- `Dependencies` и их внешняя цель не изменяются.
- Нельзя выдумывать юридические или маркетинговые сведения. Поля App Store
  заполняются только данными из репозитория либо остаются явным блокером.

## Конфигурация идентификаторов и signing

1. Базовый идентификатор в локальном `CodeSigning.xcconfig` меняется с
   `com.ben4Store` на `com.SideStore.benStore`.
2. Два iPhone SDK override главной цели в `project.pbxproj` получают тот же
   bundle ID. Это исключает расхождение archive и конфигурации расширений.
3. Получившиеся идентификаторы главного приложения, виджета и SideBackup, а
   также App Group, проверяются в Apple Developer. Недостающие capabilities,
   identifiers и provisioning profiles создаются или привязываются в пределах
   команды пользователя.
4. Применяется автоматическое signing только для нужной Release-архивации.

## Сборка и TestFlight

1. Перед изменением номера запрашивается следующий допустимый номер build в
   App Store Connect и он применяется к проекту.
2. Release archive создаётся через `asc xcode archive`, затем экспортируется
   IPA через `asc xcode export` с обновлением provisioning profiles.
3. IPA загружается только в TestFlight существующего приложения и назначается
   группе `Internal Testers` после обработки Apple.
4. Проверка завершения: в App Store Connect отображается build с ожидаемыми
   version, build number и bundle ID; состояние processing завершено либо
   точно зафиксирован блокер Apple.

## Metadata

Технические поля, которые можно надёжно извлечь из проекта, сверяются и
заполняются. Категория, privacy policy URL, описание, screenshots, возрастной
рейтинг и контактные данные не подменяются предположениями. Они нужны для
App Store или внешнего TestFlight и при отсутствии фиксируются отдельно; для
первой внутренней TestFlight-сборки это не является основанием подделывать
данные.

## Ошибки и проверка

- При несовпадении Apple identifier/profile с entitlements процесс
  останавливается до upload.
- При ошибке archive/export сохраняются только безопасные локальные логи без
  ключей и персональных идентификаторов.
- После каждого изменяющего этапа проверяются `git diff --check`, точные
  build settings и статус ASC.
